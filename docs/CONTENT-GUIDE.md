# GLAIRE — руководство по содержимому

## Общая структура

`index.html` — главная и единый мастер-макет. Секции, студия на первом экране, карта и механики общие для всех направлений. Производные HTML создаются сборкой; изменения вручную в них будут перезаписаны.

`assets/site.js` → `CONFIG_DEFAULT` содержит общие видимые тексты, контактные ссылки, медиа и QR. `STUDIO_PHOTOS` и `MASTER_PHOTOS` задают порядок фото. `LOCAL_PHOTO_VARIANTS` связывает источники с адаптивными WebP. Имена вариантов формируются динамически; проверять использование нужно по всему сопоставлению.

В JSON комментарии недопустимы. Назначение полей описано в этом руководстве; разметка, CSS и сценарии содержат комментарии по разделам.

## Данные главной: content/site.json

| Поле | Назначение |
|---|---|
| `name`, `url` | Название и основной адрес проекта. |
| `title`, `description` | Название вкладки и краткое поисковое описание главной. |
| `socialTitle`, `socialDescription` | Подписи предпросмотра ссылки. |
| `keywords`, `primaryQuery` | Темы страницы; список слов не заменяет содержание. |
| `priority` | Приоритетные направления для работы с содержанием. |
| `updatedAt` | Дата реального изменения для Sitemap. |
| `bookingUrl` | Общая ссылка виджета DIKIDI 221806. |
| `performer` | Подтверждённые сведения исполнителя: имя, статус, место оказания услуг, контакт. |

Видимый заголовок и вступление главной находятся в `CONFIG_DEFAULT`. Текущий H1 — «GLAIRE — Пространство красоты в Перми». Вступление о работе по состоянию волос сохраняется отдельно от поискового description. Не путайте эти тексты.

## Направления: content/services.json

Пять объектов создают пять страниц услуг. Вместе с главной это шесть основных страниц.

| Поле | Назначение |
|---|---|
| `slug` | Путь страницы. При смене адреса нужен редирект со старого. |
| `label` | Название в нижней навигации. |
| `title` | Название вкладки и рекомендуемый заголовок поисковой выдачи. |
| `description` | Краткое описание услуги. Поисковик может выбрать другой фрагмент. |
| `primaryQuery`, `keywords` | Основная и связанные темы страницы. |
| `oldSlugs` | Прежние адреса, согласованные с `.htaccess`. |
| `updatedAt` | Дата содержательного обновления. |
| `text` | Отличающиеся тексты внутри существующего макета. |

В `text`:

- `heroTitle`, `heroText` — видимые заголовок и вступление.
- `worksTitle`, `worksInfoLead` — заголовок и вводная раздела подхода/работ.
- `worksItemTitle1…5`, `worksItemText1…5` — пять смысловых пунктов.
- `visitText`, `visitItems` — подготовка к первому визиту.

В `visitItems` пункты разделяются настоящим переводом строки (`\n` в JSON). Внутри пункта используйте союз «и», если запятая может быть воспринята существующим редактором как разделитель.

Начальный HTML и текст после JavaScript должны совпадать. `glairePageConfig` передаёт только отличия страницы; скрытые SEO-заголовки и списки запросов не используются. Эстетическая трихология описывает очищение, пилинги и домашний уход без медицинской диагностики и лечения.

## Онлайн-запись

Штатная ссылка — `https://dikidi.net/#widget=221806`. В `assets/booking.js` задаются официальный сценарий, путь формы и резервный адрес. При смене виджета синхронно обновляют `bookingUrl`, `CONFIG_DEFAULT.bookUrl`, статические ссылки мастер-макета и константы `booking.js`.

Точки записи: `bookBtnTop`, `bookBtnHero`, `bookBtnMaster`, `bookBtnWorks`, `bookBtnBottom`, ссылка в `#serviceInfo` и кнопка результата колеса. Первые пять управляются общей настройкой `bookUrl`. Делегированный обработчик поддерживает и динамически созданную кнопку колеса.

Оформление дополнительных кнопок — `assets/booking.css`, на основе существующих `btn`. Сценарий поставщика загружается один раз после нажатия. На узком экране используется штатный переход DIKIDI; при ошибке сценария — резервный профиль. Собственных полей клиента на сайте нет. Проверка СМС-баланса и согласий проводится в DIKIDI Business.

Подключение разрешено в обеих политиках ресурсов — meta CSP в `index.html` и заголовке `.htaccess`: сценарий `https://dikidi.ru`, iframe `https://dikidi.net`. Не добавляйте глобальные `*` или `unsafe-eval`.

## Карта и фотографии

Карта — `#mapFrame` с согласованным URL Яндекса и `loading="eager"`. Не откладывайте её запуск и не назначайте повторно тот же src: это может перезагрузить карту.

Студия использует постоянную вертикальную рамку и полное изображение. Рамки мастера и работ допускают обрезку по согласованному формату. Акции сохраняют верхний край логотипа. Порядок фото внутри студии, мастера и отдельной работы не зависит от порядка карточек работ.

## Сезонный слой

Редактируемые файлы и условия перечислены в [HALLOWEEN](../HALLOWEEN.md). `event-layer.js` создаётся автоматически и вручную не меняется.

Фоновая паутина: `halloween.js` → `drawWebField`, контуры — `web-shapes-v2.svg`, размер/прозрачность — `.halloween-web-field` в `halloween.css`. Это одна поверхность с прямыми SVG-ссылками, без `pattern`, фоновых плиток или границ секций. `ResizeObserver` поддерживает длину при раскрытии карточек; обработчика отрисовки на scroll нет.

Автоматическое колесо отслеживает всю секцию `#master`, один показ при посещении каждой страницы. Ручной показ до мастера не расходует автоматический. Прямая ссылка показывает окно немедленно и считается автоматическим открытием. Эти правила не сбрасывают сохранённый приз.

## Сведения для посетителя

Карточка `footer → #serviceInfo` находится в мастер-макете и оформлена в `assets/services.css`. Она раскрывается нативным `details`, работает с клавиатуры и не создаёт согласие или договор. Это краткая информация, не замена полной политики обработки данных.

Рабочие правовые документы, отчёты и памятки не подключены к сайту. Утверждённый документ добавляют отдельным осознанным изменением после проверки фактических сведений; черновик с незаполненными пунктами не размещают как действующую политику.

## Сборка и контроль

```sh
python3 scripts/build-site.py
python3 scripts/check-site.py --rebuild
python3 scripts/preview.py
```

Сборка: праздничный сценарий → версии CSS/JS → метаданные главной → статические тексты → четыре социальных входа → пять направлений → Sitemap. Публикации эти команды не выполняют.

После изменения общих компонентов проверяют все шесть основных страниц, мобильный размер, фото, меню, карту, колесо и запись. Состояния местного редактора хранятся только в браузере: они не меняют исходники и метаданные. Публичный набор подготавливается отдельно командой `package-site.py`; документация и архивы в него не входят.
