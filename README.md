# GLAIRE Haircare Studio

Сайт студии красоты и волос GLAIRE в Перми по адресу: г. Пермь, ул. Пионерская, 15. Основная страница находится в `index.html`, админка для локального редактирования контента находится в `admin-panel.js`.

## Что загружать на хостинг

- `index.html` — основной сайт.
- `admin-panel.js` — локальная админ-панель, открывается через `?admin=1`.
- `assets/` — локальные шрифты, оптимизированные варианты всех 51 фотографии, логотип, QR-коды и браузерные иконки. Cloudinary остаётся источником видео и запасной загрузки изображений.
- `CNAME` — домен `glaire.ru` для GitHub Pages.
- `favicon.ico` — иконка вкладки браузера.
- `.nojekyll` — отключает обработку Jekyll на GitHub Pages.
- `.htaccess` — настройки HTTPS, кеша и сжатия для SpaceWeb или другого Apache-хостинга.
- `robots.txt`, `sitemap.xml`, `site.webmanifest`, `browserconfig.xml` — файлы для индексации, установки и браузерных иконок.

## Где менять контент

Большинство текстов, ссылок, фото, QR и видео лежит в объекте `CONFIG_DEFAULT` внутри `index.html`.
Массивы `STUDIO_PHOTOS` и `MASTER_PHOTOS` задают порядок 12 фотографий помещения и 14 фотографий мастера. Постоянные рамки: студия 3:4, мастер и работы 4:5, изображения акций 2:3. Только верхняя галерея студии показывает снимки целиком через `object-fit: contain`; остальные фото заполняют рамку через `cover`. Переключение не меняет высоту рамки. Стрелки располагаются поверх снимка, точки студии и мастера скрыты. Маленькие счётчики есть у фотогалерей и видео; в акциях счётчиков нет.

Для 51 фотографии подготовлены локальные WebP-варианты. До отдельного разрешения Валерия новые правки и изображения остаются только в локальном проекте. Браузер выбирает размер под ширину блока и плотность экрана через `srcset`; небольшие оригиналы не увеличиваются. Вся галерея заранее не скачивается. Новые внешние ссылки и запасная загрузка используют Cloudinary с `q_auto:good`; HEIC преобразуется в поддерживаемый браузером формат.

Подходящий размер пересчитывается при изменении ширины рамки и повороте экрана. Логотип и три QR-кода загружаются локально в WebP без потерь; иконки браузера имеют настоящий формат PNG и заявленные размеры. `sitemap.xml` перечисляет все 51 фотографии. Проверка сохранённых настроек не позволяет подставить другой адрес или номер дома вместо Пионерской, 15.

Первый снимок студии имеет пять WebP-копий 320–1280 px с качеством 86. Для остальных 50 снимков подготовлены 192 варианта 320–1280 px с качеством 82. Они находятся в `assets/images/`; соответствие исходникам задаёт `LOCAL_PHOTO_VARIANTS`. При недоступности локальной копии автоматически используется исходная Cloudinary-ссылка. Исходные ссылки и фотографии сохранены.

Интерактивная Яндекс Карта начинает загружаться сразу из HTML с `loading="eager"`, без нажатия кнопки. Повторное применение конфигурации не перезагружает тот же iframe. Видеолента не загружает ролики вне экрана; у соседних карточек подготавливаются обложки, декодируется только активный ролик. Для пользователей с уменьшением движения автопрокрутка работ отключена.

В блоке акций пять карточек, порядок: 4, 5, 1, 2, 3 — новые предложения первыми. Первые три прежних предложения сохранены. Лента прокручивается в сторону на любом размере экрана, изображения имеют одинаковый размер. Изображения закреплены по верхнему краю, включая увеличение при наведении: логотипы сверху сохраняются, обрезается только нижняя часть.

Фотографии имеют `alt` и `title`, которые обновляются при листании: «Фото мастера Валерия N», «Фото модели и пример работы мастера Валерия» с названием работы и номером кадра. `updatePhotoMetadata` создаёт 55 объектов Schema.org ImageObject с описаниями, ссылками и указанием авторства Валерия.

В галерее девять готовых работ: пять прежних и четыре новые с двумя фото в каждой. Пустые заготовки убраны. Новые работы и исходные ссылки заданы в `NEW_WORKS`, в конфигурации используются поля `newWork1`–`newWork4`. Эти же поля доступны в локальной админке. Карточки один раз перемешаны фиксированным порядком `WORKS_PROCEDURES`; порядок фотографий внутри каждой работы сохранён. `WORKS_REVISION` обновляет старые пустые значения браузера при переходе на эту версию.
Если открыть сайт с параметром `?admin=1`, появится локальная админка. Она сохраняет изменения только в браузере через `localStorage`.

SEO-данные лежат в нескольких местах и должны совпадать между собой: `<head>` в `index.html`, блок Schema.org `application/ld+json`, видимый блок контактов, `sitemap.xml` и `site.webmanifest`. Единый адрес для сайта: г. Пермь, ул. Пионерская, 15. Основные услуги: парикмахер, колорист, окрашивание, стрижки, уход, реконструкции, модификации и консультация перед записью.

## Важно

Для публикации постоянных изменений на GitHub или хостинге нужно менять файлы проекта и заново загружать их. Изменения из локальной админки видны только на том устройстве, где они были сохранены.

Если сайт выкладывается на GitHub Pages, файл `.htaccess` просто не используется. На SpaceWeb его нужно загружать вместе с остальными публичными файлами в корень сайта.

Резервные HTML сохраняются локально и не входят в публичную поставку. Служебные файлы macOS (`.DS_Store`), временные профили браузера и архивы переноса в репозиторий и на хостинг не загружаются. Исторические архивы вне папки сайта сохраняются.

Рабочие служебные пути имеют имена `.gitignore`, `.nojekyll` и `.htaccess`, с начальной точкой. При локальной подготовке публикация и совпадение с GitHub и хостингом не предполагаются: их проверяют отдельно после разрешения на выгрузку.
