# GLAIRE — Пространство красоты в Перми

Сайт GLAIRE: окрашивания, стрижки, модификации волос, реконструкции и уходы, эстетический уход за кожей головы. Адрес студии: г. Пермь, ул. Пионерская, 15. Онлайн-запись — DIKIDI.

## Запуск и проверка

Нужны Python 3 и Node.js. Установка дополнительных библиотек для сборки не требуется.

```sh
python3 scripts/build-site.py
python3 scripts/check-site.py --rebuild
python3 scripts/preview.py
```

Предпросмотр: http://127.0.0.1:8768/. Сервер доступен только на этом компьютере. Сборка обновляет файлы, проверка контролирует результат; команды не выполняют публикацию.

## Страницы

**Шесть основных страниц: главная и пять направлений.**

| Страница | Адрес |
|---|---|
| Главная | `/` |
| Окрашивания | `/okrashivaniya-perm/` |
| Стрижки | `/strizhki-volos-perm/` |

| Эстетическая трихология | `/esteticheskaya-trihologiya-perm/` |

Их адреса включены в Sitemap и нижнюю навигацию каждой страницы. Общий макет, студия на первом экране и механики сохраняются; направления отличаются содержанием и поисковыми данными.

Дополнительно существуют четыре входа для социальных карточек и события: `/glaire/`, `/halloween/`, `/halloween-bonus/`, `/halloween-surprise/`. Они имеют `noindex,follow` и не включены в Sitemap. `/404.html` — служебная страница ошибки. Таким образом, в сборке **10 входных страниц и отдельная 404**, а не 11 поисковых посадочных страниц. Проверочный файл Яндекса не является страницей для посетителя.

Прежние адреса услуг перечислены в `oldSlugs` и перенаправляются в `.htaccess`. Их прежний HTML в текущей сборке отсутствует.

## Онлайн-запись

Используется виджет DIKIDI **221806**. Кнопки есть в меню, на первом экране, после блока о мастере, рядом с работами, в финальном блоке и в раскрывающейся информации об услугах. Дополнительная плавающая кнопка не добавляется. Та же запись доступна из результата колеса.

Официальный сценарий DIKIDI загружается однократно после нажатия, не при открытии сайта. На широком экране он открывает окно поверх сайта; на узком DIKIDI открывает свою страницу записи. При ошибке подключения предусмотрен переход к профилю студии. Сайт не принимает и не сохраняет поля формы DIKIDI.

Виджет использует подтверждение телефона клиента. По инструкции DIKIDI для СМС нужен доступный баланс проекта; баланс и работоспособность отправки СМС проверяются в DIKIDI Business. Сайт не пополняет баланс и не создаёт тестовые записи автоматически.

[Официальная инструкция DIKIDI](https://support.dikidi.net/ru/knowledge-bases/4/articles/294-dobavlenie-knopki-onlajn-zapisi-na-sajte-kompanii).

## Медиа и взаимодействие

- Студия: 12 фото в согласованном порядке, рамка 3:4, полное изображение через `contain`.
- Мастер: 14 фото в согласованном порядке. Работы: девять карточек, порядок фото внутри каждой задаётся отдельно.
- Мастер и работы используют рамку 4:5 и `cover`. Акции — 2:3 с закреплённым верхним краем изображения.
- У фото и видео есть счётчики; у акций счётчиков нет.
- Локальные WebP 320–1280 px выбираются браузером по экрану. Cloudinary сохраняется как источник. `LOCAL_PHOTO_VARIANTS` формирует пути динамически: нельзя удалять файл только из-за отсутствия буквального имени в HTML.
- Видео подготавливаются при приближении секции. Музыка учитывает правила автозапуска и сохранённое выключение.
- Карта использует согласованный iframe Яндекса с `loading="eager"` и не зависит от кнопки записи.

## Сборка и размещение

Из главной собираются пять направлений и четыре социальных/праздничных входа. Их HTML не редактируют вручную. `event-layer.js` также создаётся автоматически. Версии CSS/JS в ссылках вычисляются по SHA-256 содержимого.

```sh
python3 scripts/package-site.py --output /абсолютный/путь/к/новой/папке
```

Команда создаёт папку `public/` и CSV с размерами и SHA-256, не выполняя загрузку. Назначение должно быть новой папкой вне исходников. В публичный набор не входят `content/`, `scripts/`, `docs/`, Markdown-документация, служебные файлы macOS, исторические HTML и архивы. Исходный репозиторий и файлы веб-хостинга имеют разный состав. Резервные версии сохраняются отдельно от публичной поставки.

`.htaccess` работает на Apache/SpaceWeb; GitHub Pages его не исполняет. Проверка настоящего HTTPS, публичных перенаправлений и совпадения размещённых файлов выполняется на действующем хостинге.
